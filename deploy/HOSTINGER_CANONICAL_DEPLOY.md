# مسار النشر المعتمد على هوستينجر

## الحالة الحالية (2026-08-18)

النطاق `https://smarteditor.bazarvan.com` يعمل على Supabase الذاتي داخل نفس VPS.
مسار التشغيل المعتمد هو:

`/var/www/bazarvan-editor-staging`

أزيلت عمليات PM2 القديمة (`bazarvan-editor` والعمال الستة) التي كانت تستخدم
Supabase Cloud، وحُفظت قائمة PM2 الجديدة عبر `pm2 save`. لا تُشغّل المجلد
`/var/www/bazarvan-editor` أو ملف بيئته القديم؛ فهو أرشيف محلي فقط. جميع مواضع
عبارة **Supabase SQL Editor** في هذا الدليل تعني قاعدة Supabase الذاتية على VPS،
وليس مشروع Cloud.

4. أنشئ مفتاح تشفير واحدًا بالأمر `openssl rand -base64 32` إذا لم يكن موجودًا، واحفظه باسم `AI_SETTINGS_ENCRYPTION_KEY` داخل `/var/www/bazarvan-editor-staging/.env.production`. لا تغيّر قيمة مستخدمة سابقًا قبل التأكد من فك جميع السجلات المهاجرة.
5. يدخل المسؤول الاعتمادات المشتركة من مركز المزودات الموحد، ثم يمنح كل اعتماد إما **لجميع المستخدمين** أو **لمستخدمين محددين**. لا يكفي وجود الاعتماد وحده من دون منحة مفعّلة.
6. يدخل كل مستخدم مفاتيح Gemini المجانية أو المدفوعة وأي مفتاح OpenAI API صالح، مجانيًا كان أو مدفوعًا، من إعداداته. لا يستطيع مستخدم آخر، بما فيه مستخدم عادي آخر، قراءة المفتاح أو استعماله.
7. انقل يدويًا أي مفتاح مزوّد ما زال محفوظًا في ملف Hostinger إلى اللوحة، اختبره، ثم احذف متغيرات `GEMINI_API_KEY(S)` و`GEMINI_PAID_API_KEY(S)` و`OPENAI_API_KEY(S)` و`FIRECRAWL_API_KEY` و`BROWSERLESS_API_KEY` من `.env.production` وإعداد PM2 وأعد التشغيل بـ`--update-env`.

تُشفّر القيم الخام بخوارزمية AES-256-GCM قبل تخزينها، ولا تعيدها الواجهة، ولا تستطيع أدوار Supabase من نوع `anon` أو `authenticated` قراءة جدول الخزنة. فقدان `AI_SETTINGS_ENCRYPTION_KEY` أو تغييره يجعل المفاتيح المخزنة غير قابلة للقراءة؛ احتفظ به داخل بيئة الخادم فقط وأنشئ له نسخة احتياطية آمنة. أبقِ أيضًا أسرار البنية مثل `SUPABASE_SERVICE_ROLE_KEY` و`N8N_INGEST_TOKEN` في بيئة الخادم، فهي ليست مفاتيح مزوّدين ولا تُنقل إلى اللوحة.

يضيف هذا الترحيل زر **استئناف الآن** للمهمة التي تنتظر موعد إعادة المحاولة. يبقى الاستئناف التلقائي مجدولًا حسب المدة الموجودة في **إعدادات المسؤول**، ولا يحذف الاستئناف اليدوي نتائج المنافسين المكتملة؛ يعيد العامل استخدامها ويكمل من أول منافس غير مكتمل. تعرض الواجهة نتيجة كل مقارنة مستقلة فور حفظها، ثم تعرض نتيجة الدمج النهائي كبطاقات قابلة للتطبيق في المحرر فقط.

## استيراد المقالة من رابط

قبل نشر زر **استيراد مقالة من رابط** نفّذ الترحيل التالي مرة واحدة داخل Supabase SQL Editor:

`supabase/migrations/20260731030000_article_url_import_source.sql`

يصنّف الترحيل المقالة الجديدة أو المستبدلة عبر الرابط بقيمة `source = 'import'`، ويحفظ رابط المصدر وبصمة المحتوى داخل بيانات المقالة. لا يحتاج السحب إلى مفتاح ذكاء اصطناعي أو Firecrawl، ولا ينزّل الصور.

يمكن إبقاء حدود السحب الافتراضية، أو ضبطها في `.env.production`:

```text
ARTICLE_IMPORT_TIMEOUT_MS=30000
ARTICLE_IMPORT_MAX_BYTES=4194304
```

## أوامر النشر

قبل نشر توجيه موديلات Gemini الجديد طبّق الترحيل
`supabase/migrations/20261021000000_gemini_project_quota_routing.sql`. يضيف معرّف
مشروع Google الاختياري إلى مجموعة المفاتيح، ويمنع تدوير بقية مفاتيح المشروع
نفسه بعد `429` على الموديل نفسه. اترك الحقل فارغًا إذا لم يكن المشروع معروفًا،
وافصل مفاتيح كل مشروع Google في مجموعة اعتماد مستقلة.

### سياسة النشر اليدوي المعتمدة

النشر من GitHub إلى Hostinger **يدوي فقط**. لا يوجد Workflow للنشر في GitHub
Actions، ولا Cron أو Webhook أو فحص دوري على Hostinger. بعد كل تعديل مكتمل تُرفع
النسخة إلى فرع `main`، ثم يُنفذ السحب والبناء وإعادة التشغيل يدويًا من Terminal
الخادم. يبقى Workflow **Quality gates** للفحص فقط ولا يملك صلاحية نشر.

يمكن استخدام `deploy/deploy-hostinger-production.sh` لتنفيذ الخطوات المحمية؛
فهو يقفل النشر المتزامن، ويتحقق من الالتزام المطلوب ومن نظافة نسخة الخادم ووجود
عمليات PM2، ولا يعيد تشغيلها قبل نجاح البناء، ثم يفحص `/healthz` و`/readyz`.

### خطوات النشر اليدوي

بعد تنفيذ ترحيلات Supabase المطلوبة، اتصل بالخادم عبر SSH ونفّذ:

```bash
cd /var/www/bazarvan-editor-staging
git pull --ff-only origin main
set -a
source .env.production
set +a
npm ci --include=dev
npm run build
for app in \
  bazarvan-editor-staging \
  bazarvan-staging-automation-worker \
  bazarvan-staging-ai-job-worker \
  bazarvan-staging-content-writing-worker \
  bazarvan-staging-client-page-crawler; do
  pm2 restart "$app" --update-env
done
pm2 save
curl -fsS https://smarteditor.bazarvan.com/healthz
curl -fsS https://smarteditor.bazarvan.com/readyz
```

معنى الأوامر باختصار:

- `git pull --ff-only origin main`: يسحب آخر إصدار مرفوع إلى GitHub من دون إنشاء دمج تلقائي.
- `source .env.production`: يحمّل متغيرات بيئة الإنتاج أثناء البناء وإعادة التشغيل.
- `npm ci --include=dev`: يثبت الاعتماديات طبقًا لملف القفل، بما فيها أدوات البناء
  مثل Vite حتى مع تحميل `NODE_ENV=production` من ملف البيئة.
- `npm run build`: يبني الواجهة والخادم والعوامل وينفّذ فحوص الإصدار.
- حلقة `pm2 restart`: تعيد تشغيل خادم الويب وعامل الأتمتة الموحد والعمال الثلاثة المستقلة فقط مع متغيرات البيئة المحدثة؛ لا تستخدم `pm2 restart all`.
- `pm2 save`: يحفظ قائمة العمليات لكي تعود بعد إعادة تشغيل الخادم.
- `/healthz`: يتحقق من أن خادم الويب يعمل.
- `/readyz`: يتحقق أيضًا من بناء الإنتاج، ومخططات Supabase المطلوبة، ومفتاح التشفير. يعرض حالة عامل المنافسين داخل `checks.externalAnalysisWorker` ويضع `degraded: true` عند تعطل طابوره، لكنه لا يعيد HTTP 503 بسبب تأخر مهمة وحده حتى لا تدخل مراقبة هوستينجر وPM2 في حلقة إعادة تشغيل تقطع المهام.

## ملاحظات وتشخيص المشكلات

- يشغّل PM2 خادم الويب وأربعة عمال ذاتيين من `/var/www/bazarvan-editor-staging`. هذا هو المسار المعتمد.
- أسماء العمليات الحالية تبدأ بـ`bazarvan-editor-staging` و`bazarvan-staging-*`؛ لا تُعد تشغيل الأسماء القديمة.
- لا تستخدم `/var/www/bazarvan-smarteditor` في تعليمات النشر المستقبلية إلا إذا أُعيد ضبط PM2 عمدًا للعمل منه.
- إذا لم تكن حالة النشر واضحة، اعرض جميع العمليات بالأمر `pm2 status`.
- لفحص خادم الويب استخدم `pm2 describe bazarvan-editor-staging`.
- لفحص الأتمتة والتحليل الدلالي والمنافسين والمنسقات استخدم `pm2 describe bazarvan-staging-automation-worker`، ولسجله استخدم `pm2 logs bazarvan-staging-automation-worker --lines 100`.
- إذا كان `/readyz` يعرض `degraded: true` و`checks.externalAnalysisWorker.ok: false` فخادم الويب جاهز، لكن ميزات الأتمتة متدهورة ويجب فحص `bazarvan-staging-automation-worker`. لا تعِد تشغيل خادم الويب تلقائيًا بسبب هذا التنبيه وحده.
- لفحص عامل كتابة المقالة استخدم `pm2 describe bazarvan-staging-content-writing-worker`.
- لفحص عامل زحف صفحات العملاء استخدم `pm2 describe bazarvan-staging-client-page-crawler`.
- عند فشل `/readyz` لا تعتبر النشر مكتملًا؛ راجع الترحيلات ومتغيرات البيئة وسجل العملية في PM2.
